# Mail transport API v1

Core exposes `TerribleMail\MailTransport`, `TerribleMail\Result`, and `TerribleMail\Transports::API_VERSION`. Register transports with the `terrible_mail_transports` filter after plugins have loaded. Return an associative array keyed by each transport's stable `id()`. Do not overwrite another provider's key.

The interface contains `id`, `label`, `fields`, `validate`, and `send`. Field definitions are `[label, input_type, default]`; mark secrets as `password`. Core owns encrypted configuration, capability/nonce checks, saved connection snapshots, UI, message construction, submission records, and retry policy.

`send(array $message, array $settings): Result` receives:

- Stable logical message `id` and an optional saved `connection` ID.
- `mime`, generated by the WordPress PHPMailer pipeline.
- `from`, `from_name`, and `to`/`cc`/`bcc`/`reply_to` arrays of `[address, name]`.
- `subject`, `html`, `text`, and custom header pairs.
- Attachments with filename, base64 content, MIME type, disposition, and content ID.

Respect the message's envelope and Bcc semantics. Do not leak Bcc into normal SMTP MIME. Providers that infer recipients from raw MIME must receive Bcc as required by their documented API. Do not log message bodies, tokens, raw provider error bodies, or authentication headers.

Return one of `accepted`, `rejected`, or `unknown`, with a safe user-facing detail and optional provider ID. A transport exception is conservatively treated as unknown once dispatch has begun. Only definitive rejections are eligible for the core's manual retry. Use the stable message ID for provider idempotency where supported. Do not invent delivery status from a successful submission response.

Connection configuration must remain provider-specific; API endpoint overrides in the first-party pack are test-only PHP constants, never editable browser fields. Production destinations are fixed to provider endpoints. OAuth state must be unpredictable, expiring, single-use, and bound to the authenticated administrator. Refresh tokens are stored only through core's encrypted settings.

The first-party pack is an ordinary WordPress plugin declaring `Requires Plugins: terrible-mail` and checking API version before loading its implementation. A third-party standalone module can use the same interface without depending on our Integrations pack.

Tests in `tests/connectivity.php` exercise SMTP authentication, MIME/attachments, Bcc, rejection and ambiguous outcomes, retry policy, secret handling, unavailable modules, saved connections, Resend idempotency headers, SES signature verification, Gmail raw MIME, STARTTLS/implicit TLS, and certificate-hostname rejection. `tests/web.py` covers authenticated UI operations and OAuth state/replay boundaries.
