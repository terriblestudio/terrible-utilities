# Terrible Social Images

A standalone WordPress plugin for local social cards. Choose a collection of Media Library backgrounds, a color and text color, and an overlay. Published posts and pages can have generated 1200 × 630 JPEGs. Backgrounds remain assigned to posts until removed from the collection. Cards are WordPress attachments; unchanged inputs keep their current attachment.

Cards require PHP GD with FreeType. WordPress's image editor processes the background. If an offloaded original is unavailable locally, the plugin attempts a safe HTTP download from its filtered attachment URL, subject to WordPress's HTTP safety rules and a 16 MiB limit. Private, inaccessible, or unsupported remote URLs require the offload integration to make the original locally readable. Rendering errors appear in the post's Social image panel; the last good card remains in place.

When Terrible Metadata 0.2.1 or later is active, its manually selected social image takes priority, followed by the generated card. Without Metadata or a detected SEO plugin, this plugin emits an `og:image` tag itself. Other metadata owners are not yet integrated.

The settings page suggests colors from the active theme's global palette. The default font follows the post-title, H1, heading, or site-wide font in WordPress global styles, in that order. You can instead select another registered font family or bundled Inter. WordPress theme and Font Library faces are used when their files are locally accessible and supported by the server's FreeType installation, including WOFF/WOFF2 where supported. Font family selections are not automatically inferred from arbitrary theme CSS; remotely hosted fonts and inaccessible font files are not downloaded. An unavailable selected font produces an error and preserves the last good card until an available font is selected. The site administrator should select readable colors.

In the post editor, enter an optional card title and select **Preview current title** to render an authenticated preview, including for drafts and unsaved title changes. The preview uses saved site-wide settings and does not create a Media Library item or publish the post. Generation of the published card uses WP-Cron after publication; the editor also offers manual regeneration. Use **Generate / update all cards** in Social Images settings to process existing published posts and pages after changing the design. Keep the settings page open; progress and failed post IDs are shown. Each request processes at most one post, and rerunning the operation skips unchanged cards. Per-post generation uses MySQL/MariaDB advisory locks; conflicting and stale jobs are retried through WP-Cron. Previously generated attachments are retained, including when cards are updated or the plugin is deactivated. Public social platforms need a publicly reachable card URL; short-lived signed private URLs can expire in their caches.
